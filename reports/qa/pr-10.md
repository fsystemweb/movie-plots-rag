### Minor

- **m1: ADR 001 says parametric RRF needs a server upgrade, and the PR-04 m1 wording fix is incomplete.**
  - Location: `docs/adr/001-qdrant.md:44-45`.
  - What it says: "Features added later (parametric RRF in 1.16, weighted RRF in 1.17) need both bumped".
  - Why it is wrong: my probe shows server 1.15.4 already honours `rrf.k`. ADR 002:54 correctly says only a client bump is needed, so ADR 001 contradicts it.
  - The same outdated claim remains in `docs/BACKLOG.md:23` ("only offer plain `Fusion.RRF`. Upgrading both to 1.16") and `docs/prs/PR-04.md:94` ("Qdrant 1.15.x exposes only `Fusion.RRF`"). PR-04 QA m1 explicitly asked for the PR-04 notes to be fixed.
  - Fix: in ADR 001, write "parametric RRF needs only qdrant-client ≥ 1.16 (server 1.15.4 already accepts `rrf.k`); weighted RRF (1.17) needs both". Mark BACKLOG:23 as superseded by line 28. Add a one-line correction to `docs/prs/PR-04.md:94`, or state in PR-10.md that PR-04.md is kept as a historical record.
- **m2: ADR 002's "consequence of k = 2" example holds for any k.**
  - Location: `docs/adr/002-rrf-and-parameters.md:38-39`.
  - "First in one list and absent from the other scores below second in both" is true for every k > 1. For example, with k = 60: 1/60 = 0.0167 < 2/61 = 0.0328.
  - Fix: use an example that depends on k. With k = 2, a film that is first in one list only (0.5) *ties* a film that is third in both lists (¼+¼). With k = 60, the film third in both wins (0.0323 vs 0.0167). So k = 2 rewards a single top hit much more.
- **m3: The diagram legend contradicts one arrow.**
  - Location: `README.md:40` says "Solid arrows run without credentials", but `README.md:27` `AG -->|"OpenAI-compatible API"| NEB` is solid and needs `NEBIUS_API_KEY`.
  - Fix: make that edge dashed (`AG -.->|"OpenAI-compatible API"| NEB`).
- **m4 (nit): The stray-metric guard is narrow.**
  - Location: `tests/unit/test_readme_results.py:31-32`.
  - My mutations "Hybrid reaches 88% Hit@1." and "Hybrid scores 0.94 on the fixture." outside the block both pass.
  - Fix: also reject `\d+(\.\d+)?\s*%` and two- or three-decimal figures `(?<![\d.])[01]\.\d{2,3}(?![\d.])` outside the block. Alternatively, document the heuristic's limits in the test docstring.
- **m5 (nit): The README block picks its LLM rows by position.**
  - Location: `src/movie_rag/eval/report.py`, `render_readme_block`, `_llm_rows(reports)[:7]`.
  - The slice depends on the order inside `_llm_rows` (4 RAGAS rows and then 3 agent rows). If that order changes, the README silently shows different rows.
  - Fix: select the headline rows by label, or have `_llm_rows` return the headline rows and the extra rows separately.
