## Decisions
- **ragas 0.4.3 does not import with langchain-community 0.4** (`langchain_community.chat_models.vertexai` is gone, ragas imports it unconditionally; LangChain 1.x forces community >= 0.4). `install_ragas_compat()` registers an inert stand-in class before the lazy ragas import (tested both branches) and sets `RAGAS_DO_NOT_TRACK`. Removable once ragas drops the import (backlog).
- **Abstention needs the LLM.** Spec section 1 lists abstention as a deterministic metric, but abstaining is the agent's behaviour (an answer citing no film). A retrieval-only proxy would be a score threshold: a new tunable, not in the spec, and not comparable across cosine / BM25 / RRF scores. So the abstention function is deterministic and tested, but its input is the agent's run; without a key the report says "pending credentials". It reports both correct abstention (unanswerable) and false abstention (answerable).
- **Tie-aware Hit@k / MRR** instead of the plain rank, because RRF ties are returned in varying order (hybrid Hit@1 moved 0.867 <-> 0.900 across runs). Exact when there are no ties. Kept after the retrieval tie-break (QA m1): the id order says nothing about relevance, and repeating one hybrid query 15 times showed two different result sets (the server breaks ties inside the BM25/dense lists before fusion), so a stable hybrid ranking would need client-side fusion; the metrics are what stay stable (identical in every re-run).
- **Fixture on demand**: the question set is fixture-bound, so the runner checks that every gold film is indexed and ingests the fixture if not (idempotent). A collection that also holds the full dataset would mix both; the report records the point count.
- **Smoke writes nothing** (so `make ci` leaves the tree clean) and fails below `eval.smoke_min_mrr` (0.5, config), a floor that catches a broken retrieval (e.g. in-memory hybrid) without pinning the exact numbers.
- **`unexport LLM` in the Makefile**: `make ... LLM=1` would otherwise export `LLM=1`, which pydantic-settings reads as the whole `llm:` section and rejects (found while running the CI form by hand; tested).
- **LangSmith experiments** reuse the computed rankings (target looks them up; evaluators recompute Hit@k/RR), one per mode when a key exists; a LangSmith outage marks the experiment `failed` and never fails the run. Smoke records none.
- **RAGAS inputs**: contexts are what the tools showed the agent (`Title (Year) [id]: snippet`); reference is the gold film's title, year and whole plot; unanswerable questions are not RAGAS samples (no reference). Relevancy embeddings use the local FastEmbed dense model (no second credential).
- `agent.load_mcp_tools` was split to expose `mode_interceptor(mode)` so the evaluator pins the mode exactly like production (no behaviour change; existing agent tests pass).
- Suite time (QA round 1, M1): `make test` was 376 s (QA) / 536 s (`make check`, mine); it is now **281 s** for `make lint typecheck test` (4m45 wall, 1000 passed, 99.39 %). CLI tests use a canned runner result (two keep a real in-memory run), report/runner tests a cached 8-question evaluation (`subset=` on `evaluate()`), the real-service integration test shares one evaluation (2 runs instead of 4, ~75 s -> ~40 s).
