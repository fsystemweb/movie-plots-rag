## Summary
- New `src/movie_rag/retrieval/` package: `Retriever.search(query, mode, top_k, filters)` serves `dense`, `sparse` and `hybrid` through ONE `query_points_groups` request built by `build_request`; the mode only decides the query part (one named vector, or two prefetches fused with `Fusion.RRF`).
- `SearchFilters` (`year_from`, `year_to`, `genre`, `origin`; validated, genre/origin normalised to the stored lowercase) is turned into a Qdrant filter once by `build_filter` and attached **inside each prefetch** (hybrid) or as `query_filter` (single-vector modes).
- Results are grouped by `movie_id` (`group_size=1`): one `MovieHit` per film with best chunk (`chunk_idx`), score, snippet (<= `retrieval.snippet_max_chars`) and citation fields; `Retriever.get_movie` reads the full plot from chunk 0 (`point_id(movie_id, 0)`), ready for PR-05.
- CLI `python -m movie_rag.retrieval` and `make demo` (`up` + `ingest` on the fixture + the `retrieval.demo_query` in all three modes; `Q="..."` overrides). No credentials, no LLM.
- Config: added `retrieval.demo_query`; removed `retrieval.rrf_k` (Qdrant 1.15 cannot honour it, see Decisions). 100 % coverage, 555 tests pass.

| Package | Version | Docs consulted |
|---|---|---|
| qdrant-client | 1.15.1 (pinned `>=1.15,<1.16`, server v1.15.4) | https://qdrant.tech/documentation/concepts/hybrid-queries/ (prefetch, `FusionQuery`, RRF; configurable RRF `k` is "available as of v1.16.0"), https://qdrant.tech/documentation/concepts/search/#search-groups (`query_points_groups`), https://qdrant.tech/documentation/concepts/filtering/ ; signatures confirmed on the installed package |
| fastembed | 0.9.0 | query embeddings via `Embedder.embed_dense_query` / `embed_sparse_query` (PR-03), https://qdrant.github.io/fastembed/ |

The `qdrant-hybrid` skill matches the installed version, with two differences found while testing: (1) no `RrfQuery`/`k` before 1.16; (2) qdrant-client 1.15.1's in-memory engine mishandles `query_points_groups` with prefetch (`local_collection.set_prefetch_limit_recursively` returns a bare `Prefetch(limit=...)`, dropping query, `using` and filter), so hybrid with grouping returns wrong results on `QdrantClient(":memory:")` while the real server is correct (checked against the same data).

## Decisions
- **`retrieval.rrf_k` removed.** Qdrant 1.15.x exposes only `Fusion.RRF` with a fixed constant; a setting that is silently ignored would mislead. Re-add with the qdrant-client 1.16 upgrade (backlog); only the client is the limit, the 1.15.4 server already accepts `rrf.k` over REST (PR-04 QA m1, ADR 002).
- **Filter inside each prefetch, no top-level filter in hybrid.** On the server used here a top-level filter is also pushed down into prefetches (observed, undocumented), so the shape cannot be shown to fail; the explicit per-prefetch filter is kept for being version-independent and is asserted by request-shape tests.
- **Hybrid behaviour tests need a real server.** Because of the in-memory limitation above, unit tests cover hybrid by request shape and a fake client; behaviour is covered by `tests/integration/test_retrieval_qdrant.py` where `QDRANT_URL` is set (CI; locally `export QDRANT_URL=http://localhost:6333`). Without it the integration tests run dense and sparse only (same precedent as PR-03). No skips or xfails are used.
- **No new Makefile target.** `make demo` is the retrieval-only sample query (`Q="..."` to override); ad-hoc filtered queries use `python -m movie_rag.retrieval`.
- **`get_movie` included** (small, tested) because the plan says full plots come from chunk 0; PR-05 wraps it.
- **Tracing spans** for retrieval are left to PR-05 with the MCP tool spans.
