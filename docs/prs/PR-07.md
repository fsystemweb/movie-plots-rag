## Decisions
- **Retrieval-only goes through the MCP tools, not the `Retriever` directly.** One retrieval path for the whole system (the page exercises exactly what the agent sees, including validation and error messages), no FastEmbed models or Qdrant client in the Streamlit process, and `list_filters` is an MCP tool in §1 anyway. The cost is that `make serve` must be running even without a key, which the error message says. Tests use an in-memory FastMCP client, so no socket is needed.
- **Filters in agent mode** are passed as a sentence appended to the question and the mode is pinned (existing `MovieAgent.ask(mode=)`); `top_k` is not passed (the model picks). Forcing the arguments exactly needs an interceptor change in `agent.py`; left as a follow-up rather than reopening PR-06 code.
- **The service never raises to the page**: `run_turn`, `compare`, `load_filters` return objects carrying a `UiError`. The page only renders (`st.info` for the credentials hint, `st.error` for the rest).
- **Sync service API**: each public method wraps one `asyncio.run`; one MCP session serves all calls of one action (the comparison runs its three searches over one session). No client cache (non-goal); `st.cache_resource` holds only the cheap service object.
- **Default of the switch**: retrieval-only when no key is configured, agent when one is (no new config knob).
- **`Span.trace_url()`** is a small addition to `observability.py` because the agent's span handle did not expose the run; the page wraps the agent call in a `ui.ask` span and asks for the link.
- Year slider is only sent as a filter when narrowed (the full range would silently drop films with no year).
