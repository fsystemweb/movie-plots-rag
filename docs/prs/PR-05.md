## Decisions
- **Exact-title lookup** (PR-04 QA m4): `Retriever.find_by_title` is one filtered `scroll` on `title` + `chunk_idx == 0`; exact and case-sensitive (titles are copied from search results). Titles repeat (remakes), so an ambiguous title is a `ToolError` listing `Title (Year) = movie_id` for each candidate, and `get_movie` takes an optional `year` (only with `title`) to resolve it in one more call. This is the only argument beyond the section 1 table.
- **find_similar** queries Qdrant with chunk 0's point id on the `dense` vector (no vectors transferred), grouped by film, with a `must_not movie_id` filter so no chunk of the input film can appear.
- **list_filters** uses `facet` on the indexed `genre`/`origin` fields (capped at `mcp.max_filter_values`, most frequent first, `truncated` flag) and `order_by` on the indexed `release_year`; nothing is scanned client-side.
- **Server tasks and tracing context**: the in-memory/HTTP server runs tool code in its own task, so a LangSmith tracing context must exist when the server starts; production uses env-based tracing (`configure_tracing` at startup), tests start the client inside `RunCapture`.
- **Secrets**: `span()` scrubs inputs, metadata and outputs (configured secrets and `sk-`/`lsv2_` shapes), so a key typed into a query can neither reach a trace nor make `run_metadata` raise.
- **Health route**: `/health` is a FastMCP custom route (not a tool) used by the compose healthcheck through `python -m movie_rag.mcp_server --healthcheck` (the slim image has no curl). It does not touch Qdrant; the service `depends_on` a healthy Qdrant instead.
- **Real-socket test marked `integration`**: starting the HTTP server on a loopback port is in `tests/integration/test_mcp_transports.py` (runs in `make check`, loopback only), keeping the unit suite socket-free; the unit suite covers HTTP routing with an in-process ASGI transport.
- **PR-04 QA m2 fixed** (the retrieval CLI test no longer opens a real TCP connection); **m3 not touched** (see Follow-ups).
